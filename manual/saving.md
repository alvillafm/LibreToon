# Saving and Recovery

## Save an editable project

Use **.ltoon** as your working format. Exports such as PNG and MP4 are deliveries and do not replace an editable project.

Use **Save As** for an intentional new project name. A successful save should clear the document's unsaved indicator. If an error appears, keep the document open and save to a new writable location before closing it.

## External-change warnings

If LibreToon reports that the file changed on disk, another process or another open copy may have changed it. Preserve both versions until you compare them. Do not overwrite a newer copy simply to dismiss the warning.

## Recovery and versions

**File → Program Preferences → Saving Options** contains the available automatic-save and version settings. Recovery and normal project saving serve different purposes; do not assume that a recovery file is a completed manual save.

If startup offers a recovered document, open it, inspect the latest drawings and timing, and save a separate `.ltoon` copy. Verify that copy before removing older files. Keep any existing `.backup` files until recovery is complete.

## A practical habit

At the end of a milestone, save a clearly named copy. Reopen that copy in a separate document and check a late frame. If a project fails to save, record the exact error and consult [Troubleshooting](troubleshooting.md).
